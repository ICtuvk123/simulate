# G+ 进一步优化实验

本轮没有找到足以替换原 G+ 的稳定改进。新组合 OpticalRoute（序贯光学 + 路线次序优化）已保存为实验候选，原 G+ 及先前提取包保持不变。

独立100场同场景对比：原 G+ 为235.116486秒/源，新组合为234.896563秒/源，样本均值节省0.219923秒/源（0.094%）。95%节省区间为[-0.145509, 0.635485]，跨过零，因此未通过事先设定的晋级条件。58场更快、40场更慢、2场相同；另24场压力测试双方全部清除。

## 自己跑一次

双击本目录的 **运行新候选.cmd**，运行本地模拟器中的固定场景22001。窗口会显示清除数量、行动总时间、平均每源时间和结果目录；打开结果目录中的 `replay.html` 可查看回放。

默认场景22001是一个退步案例：新候选230.851073秒/源，原 G+ 为222.871172秒/源，均14/14清除。保留该默认场景便于直观看到新候选尚不稳定，不用单场判断整体优劣。

在本目录的终端中可运行：

```powershell
.\运行新候选.cmd --seed 22002
.\运行新候选.cmd --seed 22002 --baseline
```

第一行运行新候选；第二行用相同场景运行原 G+。还可追加 `--scenario boundary` 或 `--scenario clustered` 测试边界分布或聚集分布。相同seed与相同参数才是公平的同场景对照。

这里完全使用本地模拟器，不连接官方接口，不需要团队号。官方已验证的 G+ 测试入口仍在上一层的“一键测试Gplus.cmd”。本地结果不等于官方成绩。

## 实验复现

环境：Python 3.10及以上；策略本身沿用现有环境，生成PDF另需ReportLab和本机黑体字体。启动脚本优先使用本机现有的Python环境，不自动安装依赖。

`code/` 为冻结源码，`candidate.json` 为本轮选定配置；`runs/` 保存原始动作、结果和源码快照。`screen16.json` 和 `development40.json` 是开发场景，`validation100.json` 和 `stress24.json` 是选型冻结后使用的新场景。不要用独立验证集反复调参后仍称其为独立验证。

运行新批次前复制场景配置、使用新的phase名称（已有批次目录不覆盖）。`batch.py 配置.json` 运行批次，`compare.py 阶段名` 进行完整性核对和配对统计，`audit_replay.py 阶段名` 验证冻结策略仅凭反馈复现原动作。完整源码和配置必须保持对应。

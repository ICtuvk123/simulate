# G+ 自助测试

双击本文件旁的 **一键测试Gplus.cmd**，打开中文测试窗口。团队号已填为 **202617201735**，官方接口端口默认为 **2026**。保持整个 `jammer_search_q3` 文件夹完整，不要只移动启动文件。

## 在官方模拟器里测试

1. 打开官方模拟器，用团队号 `202617201735` 登录。
2. 选择 **问题3演练测试**，等待 5 秒准备倒计时结束，页面显示接口已开放。
3. 在测试窗口的“官方演练”页，复制填入**当前案例编号**，形如 `XXXX-XXXX-XXXX-XXXX`。
4. 核对队号、端口及官方页面后，勾选就绪选项，点击开始。每次点击运行一场 G+ 演练。
5. 运行结束，窗口显示清除数量、总行动时间和平均时间。请在官方结束页面核对是否全部清除，并从官方日志列表导出本场 `.jlog`，保存到本次结果文件夹。

案例编号要从当前页面复制，不能拿之前的编号代替。程序会检查重复案例。官方 HTTP 接口不返回当前测试模式，所以需要你核对页面后勾选就绪；程序据此连接本机接口。

## 先在本地熟悉操作

切换“本地测试”，保留场景编号 `13001`，运行 G+ 即可。这里不需要登录或打开官方模拟器。

想检查是否变快：在**相同场景编号**下，分别运行 G+ 和原 G 对照，再比较平均时间。更换场景编号可以测试另一组随机场景。单个场景不能代表整体改进，多场比较时应让两种策略使用同一组编号，并先检查全部清除与完成证明。

本地每次会生成一个 `replay.html`，其完整路径显示在结果中。双击该文件可播放搜索过程。

## 查看结果

点击窗口中的结果文件夹按钮，或打开项目根目录的 `user_tests`。每次测试各有一个带时间戳的文件夹，之前的结果会保留。

- `测试结果.txt`：中文结果，可直接打开或分享。
- `test_result.json`：可用于汇总的数值结果。
- `console.log`：底层运行输出。
- `launch_config.json`：本次队号、案例或本地场景等启动设置。
- 失败时额外生成 `error.log`；保留它及官方当前页面以便定位原因。

完整动作日志与代码快照保存在结果中标明的“原始运行记录”目录。官方演练保存在 `training_logs`，本地测试保存在 `time_push_20260912/runs`。

**平均时间 = 本次总行动时间 ÷ 本次清除数，单位为秒/源。** 窗口等待了多久是电脑计算和通信耗时，与题目的行动时间不同。未完整通过的运行只显示诊断均时；官方总源数和最终成绩以官方结束页面为准。

## 遇到问题

- 先点“环境检查”：核验 Python 和 16 个 G+ 冻结文件，此操作不会连接官方模拟器。
- 无法连接：核对模拟器已开启、端口一致、倒计时已结束。若已启动过当前案例，请先保留页面和日志排查，避免重复运行。
- 冻结文件校验失败：说明当前算法或参数与已验证版本不一致，恢复原文件后再运行。
- 找不到 Python：本机启动器优先使用已有 Python，也支持系统的 Python 3.10 或以上。测试代码仅使用标准库，无需安装额外 Python 包。

需要命令行时，在项目根目录的 PowerShell 中执行：

```powershell
.\一键测试Gplus.cmd --check
.\一键测试Gplus.cmd --local --seed 13001
.\一键测试Gplus.cmd --local --seed 13001 --baseline
```
